# Schema 选择研究笔记（合成数据）

> ⚠️ 本文档为合成演示资料，非真实论文或实验结果。

## 研究背景

Text-to-SQL 任务需要将自然语言问题转换为 SQL 查询。Schema 选择是其中的关键步骤：
从数据库中选出与问题相关的表和列，作为 LLM 生成 SQL 的上下文。

## 主要发现

1. **高召回 vs 精确度权衡**：保留更多候选 Schema 可能提高召回率，但也可能引入噪声。
2. **冗余候选影响**：当候选 Schema 中包含大量无关表时，LLM 可能生成不准确的 SQL。
3. **JOIN 条件敏感性**：涉及多表 JOIN 的问题对 Schema 选择错误特别敏感。

## 待验证假设

- 冗余候选 Schema 是否显著降低生成准确率？
- 是否存在最优的候选数量阈值？

## 个人判断

我认为应该先检查 JOIN 条件相关的失败案例，再决定是否需要更精细的过滤策略。
